LRD Stabilizer v7 — Architecture Redesign
Background
Six training runs have identified two root causes of failure that require architectural changes rather than hyperparameter tuning:

Gate discrimination failure: gate fires identically on clean and perturbed inputs (noisy/clean ratio ~1.004–1.048 across all runs) because mid-network hidden states at layers 1–8 have already had divergence suppressed by Phi-3.5's spike-and-suppress pattern. There is genuinely not enough signal at those layers for the gate to discriminate on.
Correction direction bias: single shared MLP learns one correction direction dominated by large-displacement perturbations (whitespace, speech). Character-substitution perturbations (typos, OCR) produce subtler displacements that get drowned out in the gradient signal, resulting in a correction direction that actively hurts those conditions.

Both failures trace to the same root cause: intervening at layers 1–8 is causally effective (confirmed by patching) but the perturbation signal at those layers is weak due to spike-and-suppress collapsing LRD by layer 3. The richest signal is at the embedding layer (layer 0) where LRD peaks before suppression begins.
Architecture Changes
Replace the current single-stage insertion at layers 1–8 with a two-stage design:
Stage 1 — Primary correction at embedding layer

Insert before layer 0, operating directly on token embeddings
Gate reads raw token embeddings — character-level perturbations are directly visible here as embedding distance, giving the gate a real discrimination signal for the first time
Correction mechanism: norm-clipped bottleneck MLP (keep from v5/v6, it works)
Objective: contrastive rather than MSE reconstruction — push corrected embedding closer to h_clean_embedding than h_noisy_embedding is, without requiring exact match
Contrastive loss: L_contrastive = max(0, d(h_corrected, h_clean) - d(h_noisy, h_clean) + margin), where d is cosine distance and margin ~0.1
This naturally handles non-failure-predictive perturbations (case, whitespace): if h_noisy is already close enough to h_clean, loss is near zero and correction is small

Stage 2 — Refinement at layers 2 and 4 only

Light correction modules at layers 2 and 4 (not 1–8)
Same norm-clipped bottleneck MLP architecture but smaller bottleneck (32 vs 64)
Standard MSE reconstruction objective against h_clean at those layers
These handle residual divergence that survived Phi-3.5's suppression
Gate at these layers reads hidden state as before — low signal expected, these modules should apply small corrections only

Loss Function
L_total = λ_contrast · L_contrastive        # stage 1, noisy steps only
        + λ_stab · L_stab                   # stage 2 MSE, layers 2+4, noisy steps
        + λ_prop · L_prop                   # probe at layer 9 only (1 frozen layer gap, avoids vanishing gradients)
        + λ_acc · L_acc                     # task CE, both steps
        + λ_gate · L_gate_max               # max-based sparsity, both steps
        + λ_suppress · L_suppress           # clean step gate suppression
        + λ_adapter · L_adapter_clean       # adapter output norm on clean steps
Starting weights:

λ_contrast = 0.35
λ_stab = 0.15
λ_prop = 0.10
λ_acc = 0.40 (keep as independent floor, not derived from others)
λ_gate = 0.15
λ_suppress = 0.20
λ_adapter = 0.15

Drop L_dir (cosine alignment) — absorbed into L_contrastive which is more principled.
Drop L_lrd (LRD gate supervision) — the embedding-level gate has direct access to perturbation signal now, explicit LRD supervision is no longer needed.
Gate Changes
Stage 1 gate input: raw token embeddings concatenated with per-token embedding norm deviation from clean EMA — concat([emb, |emb - emb_clean_mean|]). At the embedding level this deviation is directly meaningful: a character substitution changes the embedding vector visibly. No warmup needed for EMA here since embedding distributions are stable from step 0.
Stage 2 gate input: hidden state only (same as before) — these gates are expected to stay mostly closed, acting as a safety valve rather than a primary correction mechanism.
Remove EMA-based gate input augmentation from stage 2 — it didn't help at mid-network layers and adds complexity without benefit.
Training Data
Use multidomain mix: 40% GSM8K, 30% MMLU, 30% C4/general web. Same perturbation augmentation applied to all sources. This is already running in v6b — use that data pipeline.
Curriculum

Steps 0–2000: heavy regularization dominance (reg_mult = 2.0), gate stays closed, adapter learns near-zero corrections
Steps 2000–8000: gradual ramp, reg_mult decays 2.0 → 1.0
Steps 8000–25000: standard weights as above, gate free to open based on learned discrimination
Monitor gate_ratio_stage1 (noisy/clean) at step 3000 — target > 1.3. If still near 1.0, the embedding-level signal isn't working and the design needs revisiting before continuing.

Key Metrics to Log

gate_ratio_stage1 and gate_ratio_stage2 separately
gate_cond_{perturbation_type} for stage 1 and stage 2 independently
L_contrastive per perturbation type — should be higher for typos/OCR than speech/whitespace if the contrastive objective is working
adapter_norm_stage1 and adapter_norm_stage2 separately
Per-condition eval at steps 5000, 10000, 15000, 20000, 25000 on held-out GSM8K

What success looks like at step 3000

gate_ratio_stage1 > 1.3 (embedding gate discriminating)
gate_ratio_stage2 near 1.0 (mid-network gates still closed, expected)
L_contrastive higher on typos/OCR steps than speech/whitespace steps
L_acc stable in 0.4–0.8 range, not collapsing

What failure looks like at step 3000

gate_ratio_stage1 still near 1.0 — embedding signal not sufficient, architectural assumption wrong
L_acc collapsing toward 0.1 — shortcut re-emerging, check prompt masking is still applied at embedding stage
adapter_norm_stage1 growing rapidly — norm clip too loose, reduce max_norm

Preserve from v6

Prompt-position masking (critical — must apply at embedding stage too)
Norm-clipped bottleneck MLP architecture
Max-based gate sparsity penalty
Per-condition training weights (whitespace downweighted 0.3×)
Multidomain training pipeline from v6b


The most important thing to check before submitting the full 25k run is the step-3000 gate_ratio_stage1 diagnostic. Every previous run has shown gate failure within the first 3000 steps when it was going to fail. If the embedding-level gate is discriminating at step 3000, you have a fundamentally different training dynamic than anything you've seen before and the full run is worth completing.
